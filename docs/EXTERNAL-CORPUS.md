本目录的冻结文件不是自制样本，而是**从 openFDA 原样取回、未加工、可离线核验**的登记记录。

核验方式（**不需要联网**）：

```bash
python tools/fetch_openfda_510k.py --verify data/openfda_510k_software.json
python -m unittest tests.test_openfda_freeze      # CI 里跑，改文件不改 manifest 即红
```

## 这份语料能证明什么

1. 记录**来自外部**（URL、查询语句、抓取时间、记录数全部写在 manifest 里）；
2. 记录**没被改过**（哈希随文件提交，第三方重算即可比对）；
3. 复现路径是脚本化的，任何人可重跑同一查询。

## 这份语料**不能**证明什么（必须写清，否则就是夸大）

- **不是 AI 器械队列**。`device_name` 含 "software" 只能说明名称里有这个词；同一关键词在 openFDA 里
  横跨 1985–2026，混着老式影像软件与近年的算法器械。因此**不能**据此算"AI 器械占比"。
- **拿不到 PCCP 事实**。510(k) 的 JSON 里只有登记字段（K 号、器械名、申请号、决议日期、产品码、
  `statement_or_summary` 标记），**PCCP 的内容写在 summary PDF 里**，本仓不做 PDF 抽取，
  所以无法从这份语料判断"是否带 PCCP"。
- 外面对"AI 器械带 PCCP 只有 5.4%"的说法（43/794），来源是第三方统计，**本仓未复核**，
  引用时必须标为他人数据。

## 要走到"真实 PCCP 材料回放"，还差什么

1. **拿到 summary PDF**：510(k) summary 可从 FDA 510(k) 数据库页面下载，需逐个抓取并留档；
2. **人工编码**：把 PDF 里的"是否声明 PCCP、声明了哪类变更、验证是否完成"编码成判定器输入字段——
   这一步**必须人工双人标注**，机器猜等于造假；
3. **只有做完 1+2**，`lcas` 的判定才有"真实案例"可言。在此之前，对外只能称：
   "在自建案例集与外部登记记录上可复跑"，不能称"经真实申报件验证"。

## 抓取口径（供复核）

- 源：`https://api.fda.gov/device/510k.json`
- 分页：`limit≤100`、`skip` 递增、每页间隔 200 ms，不对上游施压
- 哈希口径：`records` 数组的规范化 JSON（`sort_keys=True, indent=2`），UTF-8
- 只存登记字段，不加工、不推断、不合并
